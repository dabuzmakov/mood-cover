## Требования MR3

- [ ] Параметр `--threads` работает
- [ ] Результаты потоков корректно объединяются
- [ ] **Нет race condition**
      (рекомендация: локальные буферы на поток, слияние без общей записи)
- [ ] Benchmark-режим со сравнением 1, 2, 4 и 8 потоков:

```text
dotnet run -- benchmark --config config.json --threads 1,2,4,8 --output benchmark.md
```

### Отчёт содержит

- [ ] Конфиг и seed
- [ ] Время для каждого числа потоков
- [ ] Ускорение относительно одного потока
- [ ] Путь к PNG

```text
| Threads | Time ms | Speedup |
| 1       | 8200    | 1.00    |
| 4       | 2900    | 2.83    |
```

**Честная оговорка.** Многопоточная версия не обязана давать пиксель-в-пиксель
тот же PNG, что однопоточная, если порядок генерации точек другой. Но при
одинаковых конфиге, seed **и числе потоков** результат должен быть
воспроизводимым. И не жди ускорения на маленьком числе итераций — накладные
расходы на потоки тоже стоят времени.
