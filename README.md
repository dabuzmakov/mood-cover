# MoodCover

MoodCover — генератор цветных PNG-изображений на C# на основе алгоритма **fractal flame** и идеи **Chaos Game**. Изображение строится из последовательности случайных преобразований точки: попадания в пиксели накапливаются в буфере, а затем преобразуются в цвет и яркость.

Первый MR по плану проекта включает ядро рендерера и сохранение PNG: входную модель параметров, обработку одной цепочки точек, параллельный запуск независимых цепочек и объединение их буферов. Параметры запуска пока заданы непосредственно в коде.

## Запуск генерации

Нужен **.NET SDK 10**. Команды выполняются из корня проекта.

```bash
dotnet run --project src/MoodCover.App
```

Результат сохраняется в `image.png` в рабочей папке процесса. При запуске этой командой из корня проекта файл появится в корне. Существующий файл перезаписывается.

## Генерация точек

`FractalFlameOptions` передаёт рендереру размеры изображения, число итераций и цепочек, seed, палитру, список аффинных преобразований и вариации с весами.

Для каждой цепочки выбираются начальная точка и начальная цветовая координата. На каждой итерации:

1. Равновероятно выбирается набор аффинных коэффициентов.
2. К точке применяется аффинное преобразование:

   ```text
   xNew = a * x + b * y + c
   yNew = d * x + e * y + f
   ```

3. `WeightedRandom<IVariation>` выбирает одну вариацию с вероятностью, пропорциональной её весу, и применяет её к полученной точке.
4. Цветовая координата обновляется по формуле `0.4 × текущая + 0.6 × координата выбранного аффинного набора`.
5. Точка переводится в координаты пикселя. Если она попала в границы изображения, в локальный буфер добавляются попадание и RGB-цвет из палитры.

Точки за пределами изображения не записываются в буфер, но продолжают участвовать в цепочке. Масштаб по обеим осям одинаковый и зависит от высоты изображения; начало координат находится в его центре.

## Вариации и палитры

Реализованы восемь вариаций: `linear`, `sinusoidal`, `spherical`, `swirl`, `horseshoe`, `polar`, `heart`, `disk`. Каждая реализует `IVariation` и преобразует пару координат `(x, y)`. В `spherical` и `horseshoe` предусмотрена обработка нулевого радиуса.

`GradientPalette` получает координату от `0` до `1` и линейно интерполирует RGB-цвет между соседними опорными цветами. В приложении зарегистрированы палитры `warm`, `cold`, `neon`, `pastel`, `mono` и `rainbow`.

`NamedRegistry<T>` находит вариации и палитры по имени без учёта регистра. Для добавления новой вариации достаточно реализовать `IVariation` и зарегистрировать её в приложении.

## Параллельный рендеринг

`AccumulateHitsAsync` делит общее число итераций между независимыми цепочками. Остаток распределяется по одной итерации между первыми цепочками. Число цепочек ограничено количеством итераций.

При одной цепочке вычисление выполняется напрямую. При нескольких каждая запускается через `Task.Run` и использует собственные `Random` и двумерный буфер `PixelAccumulator[,]`. Общей записи в пиксели во время генерации нет. После `Task.WhenAll` буферы последовательно объединяются: складываются числа попаданий и суммы RGB-каналов.

Seed каждой цепочки выводится из общего seed до запуска задач. Цветовые координаты аффинных наборов также создаются заранее и используются только для чтения. При одинаковых параметрах, seed и числе цепочек порядок завершения задач не меняет результат. Изменение числа цепочек меняет последовательности случайных чисел и может изменить изображение.

Каждая цепочка хранит полноразмерный буфер, поэтому расход памяти растёт пропорционально произведению ширины, высоты и числа цепочек. Значение `Threads` задаёт число задач рендеринга; их выполнение планирует пул потоков .NET.

## Формирование PNG

`PixelAccumulator` хранит число попаданий и суммы красного, зелёного и синего каналов. При формировании изображения вычисляется средний цвет пикселя, а яркость определяется логарифмом плотности попаданий:

```text
brightness = log(1 + hits) / log(1 + maxHits)
correctedBrightness = brightness ^ (1 / gamma)
```

Пиксели без попаданий остаются чёрными. `PngImageSaver` сохраняет изображение через **SixLabors.ImageSharp**, проверяет расширение `.png` и положительное конечное значение `gamma`. По умолчанию `gamma = 1`, то есть дополнительная гамма-коррекция не применяется.
